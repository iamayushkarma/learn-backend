1) BACKEND BASICS (MUST BE SOLID)
====================================================================

1.1 HTTP / HTTPS (CORE WEB PROTOCOL)
------------------------------------

A) HTTP Fundamentals
- Client–server model
- Request–response lifecycle
- URL anatomy: scheme, host, port, path, query, fragment
- Idempotency & safety of methods
- Content negotiation basics (Accept, Content-Type)

B) HTTP Methods (Know purpose + rules)
- GET: fetch resources, safe, idempotent
- POST: create or trigger processing, not idempotent
- PUT: replace full resource, idempotent
- PATCH: partial update, not necessarily idempotent
- DELETE: remove resource, idempotent (behavior can vary)
- HEAD: like GET without body
- OPTIONS: discover server capabilities (important for CORS)
- TRACE/CONNECT (awareness-level)

C) Status Codes (Must recognize patterns)
- 1xx informational (rare in app dev)
- 2xx success:
  - 200 OK
  - 201 Created (+ Location header)
  - 202 Accepted (async processing)
  - 204 No Content (no response body)
- 3xx redirects:
  - 301/308 permanent
  - 302/307 temporary
  - 304 Not Modified (caching)
- 4xx client errors:
  - 400 Bad Request (validation/format)
  - 401 Unauthorized (not authenticated)
  - 403 Forbidden (authenticated but not allowed)
  - 404 Not Found
  - 405 Method Not Allowed
  - 409 Conflict (duplicate/merge conflicts)
  - 415 Unsupported Media Type
  - 422 Unprocessable Entity (validation semantics; optional)
  - 429 Too Many Requests (rate limit)
- 5xx server errors:
  - 500 Internal Server Error
  - 502 Bad Gateway
  - 503 Service Unavailable
  - 504 Gateway Timeout

D) Headers (Know key ones + use cases)
- Request headers:
  - Authorization (Bearer, Basic)
  - Content-Type
  - Accept
  - User-Agent
  - Origin
  - Referer
  - Cookie
  - If-None-Match / If-Modified-Since (caching)
- Response headers:
  - Set-Cookie
  - Cache-Control
  - ETag / Last-Modified
  - Location
  - Access-Control-* (CORS)
  - Content-Security-Policy (security)
  - Strict-Transport-Security (HSTS)
  - X-Content-Type-Options, X-Frame-Options (legacy but common)

E) Cookies (Must be precise)
- What cookies are (key-value stored by browser)
- Cookie scopes: domain, path
- Expiration: session vs persistent cookies
- Security flags:
  - HttpOnly (JS cannot read)
  - Secure (HTTPS only)
  - SameSite (Lax/Strict/None)
- Cookies vs tokens (tradeoffs)
- CSRF relation: why cookies can be risky without defenses

F) HTTPS + TLS (Practical understanding)
- Why HTTPS matters: confidentiality, integrity, authenticity
- TLS handshake conceptually
- Certificates, CA, certificate chain (basic)
- Mixed content problems
- HSTS concept

Skill Checkpoints
- Can read raw HTTP request/response and explain each part
- Can choose correct method + status code for an API action
- Can design headers/caching behavior for endpoints
- Can configure cookies safely for sessions

------------------------------------------------------------

1.2 REST (RESOURCE DESIGN + API SHAPE)
--------------------------------------

A) Core REST Concepts
- Resources (nouns), not actions (verbs)
- Representations (JSON)
- Statelessness
- Consistent URL structures
- HATEOAS (awareness-level; rarely used strictly)

B) Resource Design Patterns
- Collections vs single resource:
  - /users
  - /users/:id
- Nested resources:
  - /users/:id/orders
- When NOT to nest deeply
- Actions that don’t map neatly:
  - /auth/login
  - /users/:id/activate (or PATCH status)

C) Consistent Response Design
- Standard response envelopes vs plain objects (pick one style)
- Error response shape:
  - message
  - code
  - details (validation errors)
  - requestId/traceId (optional but useful)

D) Pagination (Must know multiple styles)
- Offset-based pagination:
  - ?page=2&limit=20 or ?offset=20&limit=20
  - Pros/cons (duplicate/missing items if data changes)
- Cursor-based pagination:
  - ?cursor=abc&limit=20
  - Pros/cons (stable ordering; more complex)
- Return pagination metadata:
  - total count (optional)
  - nextCursor
  - hasNext
- Sorting requirement for pagination stability

E) Filtering + Searching
- Query filters:
  - ?status=active&role=admin
- Range filters:
  - ?minPrice=100&maxPrice=500
  - dates: ?from=2026-01-01&to=2026-01-31
- Full-text search (basic awareness; usually DB-driven)

F) Sorting
- ?sort=createdAt or ?sort=-createdAt
- Multiple sorts: ?sort=createdAt,-price
- Validate allowed fields to prevent abuse

G) Versioning
- URL versioning: /api/v1
- Header-based versioning (awareness)
- Deprecation strategy (concept-level)

Skill Checkpoints
- Can design REST endpoints for a full CRUD resource
- Can implement pagination + filtering + sorting consistently
- Can produce predictable, documented error responses

1.3 AUTHENTICATION VS AUTHORIZATION
-----------------------------------

A) Definitions (Must be crystal clear)
- Authentication: who you are (identity)
- Authorization: what you can do (permissions)

B) Common Auth Approaches
- Session-based auth (cookies)
- Token-based auth (JWT access tokens)
- API keys (service-to-service)
- OAuth 2.0 (authorization delegation concept)
- OpenID Connect (identity layer on OAuth2 concept)

C) Authorization Models
- Role-Based Access Control (RBAC)
- Attribute-Based Access Control (ABAC) (awareness)
- Ownership checks (resource-level permissions)

D) Security Concerns
- Password hashing (bcrypt/argon2 concept)
- Brute force protection (rate limits, lockouts)
- Token expiry + refresh tokens
- Secure storage:
  - cookies with HttpOnly + Secure
  - avoid localStorage for sensitive tokens if possible (context-based)
- Replay risks and invalidation strategies

Skill Checkpoints
- Can explain session vs JWT tradeoffs
- Can enforce permissions at route + resource level
- Can reason about common auth vulnerabilities

1.4 CORS (CROSS-ORIGIN RESOURCE SHARING)
----------------------------------------

A) Why CORS Exists
- Same-Origin Policy in browsers
- “Origin” definition: scheme + domain + port
- Why servers must explicitly allow cross-origin calls

B) Simple Requests vs Preflight
- Simple requests requirements (method + headers limitations)
- Preflight requests:
  - OPTIONS request
  - Access-Control-Request-Method
  - Access-Control-Request-Headers

C) Key CORS Headers
- Access-Control-Allow-Origin
- Access-Control-Allow-Methods
- Access-Control-Allow-Headers
- Access-Control-Allow-Credentials
- Access-Control-Expose-Headers
- Access-Control-Max-Age

D) Cookies & Credentials with CORS (Common pitfall)
- When sending cookies cross-origin:
  - client must send credentials
  - server must allow credentials
  - Allow-Origin cannot be "*"
- SameSite=None requires Secure

E) Correct Configuration Patterns
- Allowlist origins (recommended)
- Environment-based config (dev vs prod)
- Handling multiple origins safely

Skill Checkpoints
- Can debug a CORS error by reading browser console + network tab
- Can correctly configure CORS for:
  - SPA (React) → API
  - cookies-based sessions
  - token-based auth

- Event-driven, non-blocking I/O

- Different globals (process, Buffer, __dirname in CJS)

C) Event Loop Deep Understanding
- Call stack, task queue, microtask queue
- Timers phase, I/O callbacks, poll, check, close callbacks

  - Promises (.then/.catch/.finally)

- Practical effect on performance & “blocking”

D) Concurrency Model
- Asynchronous I/O
- Worker threads (CPU-bound tasks)
- Child processes
- Cluster (multiple processes behind same port)
- When to use which

Skill Checkpoints
